# Lessons

One line each, added through PRs by pipeline runs and curated by a maintainer. Workers read this before every run.

- Cloud sessions: if `wp-env` fails with "Cannot connect to the Docker daemon", the container restarted and dockerd is gone; re-run `bin/cloud-setup <repo>` (`bin/check` does this on its own).
- Read-only production checks: wordpress.org answers a plain `curl` with 403 (nginx); pass a browser User-Agent (`-A "Mozilla/5.0"`), and treat a 403 as a fetch failure, not as the page's state.
- Standalone JS block screenshots: Chromium here cannot load `localhost:8888` from another origin, so `curl` the `wp-includes/js/dist` scripts into the harness and serve them with `page.route`; Playwright routes do not intercept redirect targets, so stub `window.fetch` with `addInitScript` to simulate an mShots redirect.
- WordPress 7.2's kses decodes numeric character references (r64233): content encoded before kses (`&#91;`, `&#045;`) comes back decoded, so encode after kses.
- bbPress's Akismet integration (`includes/extend/akismet.php`) sets caught posts to spam, never pending, so a forum post held in the pending queue was put there by the moderation-keys check, a wporg filter, or a moderator, not by Akismet.
- pattern-directory: the wp-env site caches PHP for a few seconds, so wait before re-requesting a page after swapping files for before/after screenshots.
- pattern-directory: wp-env starts with no patterns; grids only list patterns with `wpop_locale` meta (`wp post meta update <id> wpop_locale en_US`), and `wporg-pattern-favorites` meta sets the favorite count. Create `my-patterns` and `favorites` pages with `wp post create --post_type=page --post_name=...`.
- pattern-directory: wp-env has no `new-pattern` page; build the theme and directory too, create it with `wp post create --post_type=page --post_name=new-pattern --post_status=publish`, flush rewrites, log in as admin/password, and close the welcome guide (`.components-modal__frame button[aria-label="Close"]`), which otherwise disables the Settings toggle. The sidebar open state is saved per user, so check `aria-expanded` before clicking it.
- pattern-directory: `record_snapshot()` returns early under `WPORG_SANDBOXED` (set in wp-env), so to test the Stats screen or its CSV export, insert a `wporg-pattern-stats` post with `get_snapshot_data()` as `meta_input` via `wp eval`; the export form only renders once a snapshot exists.
- pattern-directory: run single creator Jest files from `plugins/pattern-creator` (its `jest.config.js` maps `@wordpress/*`; from the repo root they fail on ESM). wp-env has no `PATTERN_OV_OAUTH_ID`, so the Openverse search fatals; for screenshots, stub `/wporg/v1/openverse/search` and the image URLs with Playwright `page.route`.
- wordcamp.org: for phpcs on changed lines, `composer update` from a temp copy of `composer-dev.json` and set phpcs `installed_paths` by hand, since Composer plugins are disabled.
- wordcamp.org: the "WordCamp Groups Network" suite (`mu-plugins/groups/tests`) holds the groups-site theme tests; in it, set `site_admins` with `update_site_option()` instead of `grant_super_admin()` (it fails in a full run), and `register_theme_directory( SUT_WP_CONTENT_DIR . 'themes' )` before `groups-site`'s template parts resolve.
- wordpress.org: the plugin-directory test env maps the wporg-plugins-2024 theme, so its template parts can be tested from `plugin-directory/tests` via `WP_CONTENT_DIR . '/themes/wporg-plugins-2024/...'`; `wp_kses()` output lowercases and re-quotes attributes, so assert with `WP_HTML_Tag_Processor`, not raw strings.
- wordpress.org: a fatal `Undefined constant WPORG_PLUGIN_DIRECTORY_BLOGID` in the plugin-directory wp-env means a stale database; run `wp-env destroy` and start again (`bin/test-wordpress-org` does this on its own).
- wordpress.org: Trac config/templates (`trac.wordpress.org/`) can be checked locally: `pip install` the Trac 1.6 sdist into a venv, `trac-admin <env> initenv`, add `file = <repo>/trac.wordpress.org/conf/common.ini` under `[inherit]`, then run `tracd` and curl a page; note `initenv` writes every default into the env's own `trac.ini`, which overrides inherited values.
- wordpress.org: `support-helphub` was synced from the archived WordPress/wporg-documentation-2022 repo, and a sync from there can delete files that exist only in Meta; fix it in Meta.
- wporg-developer: the search autocomplete can be checked on the live site without wp-env. Load the page in Playwright, answer `admin-ajax.php` with a local `page.route` fulfill (register it before any rule that aborts non-GET requests, since the call is a `$.post`), and inject candidate CSS with `addStyleTag`.
- wporg-main-2022: `setup:wp` cannot import content, so create pages with `wp post create --page_template=<template>`.
- wporg-mu-plugins: `vendor/` is ~6 GB and `~/.cache/composer` another ~6 GB, so a second `git worktree` with its own `bin/check` fills the disk; fix two items one after the other in the main checkout. To screenshot the Table of Contents block in wp-env, render it before `post-content` in the template, since it injects heading ids through a `the_content` filter.
- wporg-mu-plugins: the wp-env dev site renders no global header; create a page with `<!-- wp:wporg/global-header /-->` via `wp post create`, and since localhost never matches a menu URL, add `current-menu-item` in the browser to capture active states (the default theme zeroes submenu link padding, unlike production).
- wporg-mu-plugins: Chromium has no text-only zoom; to check the global header against it, `addStyleTag` a larger `font-size` on the top-level menu links and `.global-header__desktop-get-wordpress` without resizing the viewport, and screenshot a clip taller than `.global-header`, since wrapped items render below it.
- Read-only production checks: parallel Playwright loads of events.wordpress.org pages can come back without stylesheets (likely throttling), which skews measurements; load pages one at a time and confirm a styled value (such as a computed padding) before measuring or screenshotting.
- Learn: if `composer install` fails on an unreachable `wporg/wporg-mu-plugins` lock commit, `vendor/` still holds the PHPCS standards; run `vendor/bin/phpcs --runtime-set installed_paths <wpcs,phpcompatibility/*,phpcsstandards/* paths>`. The Profiles hooks in `inc/profiles.php` are disabled when the environment type is `local`, so wp-env cannot exercise them.
- wporg-two-factor: `pecl install xdebug` cannot reach pecl.php.net from the cloud, so the `wp-env start --xdebug=coverage` check fails; run `npx wp-env start` then `npm test` for PHPUnit. Run `wp-scripts lint-js --fix` only from `settings/` on the file you changed: from the repo root it picks up another config and reformats every file.
- wordcamp.org: to test CampTix admin Backbone/jQuery UI JS without wp-env, load jQuery, jQuery UI, Underscore and Backbone from `/tmp/wp/wordpress/wp-includes/js` (the PHPUnit install step downloads it; cdnjs answers 403 here) into a `file://` page with the `<script type="text/template">` copied from the PHP view. A `git worktree` has none of the gitignored `vendor/`, `mu-plugins-private` or plugins, so run checks in the main checkout.
- Learn: `wp-env start` fails in the cloud while building its image (`apt-get install $PHPIZE_DEPS` exits 100), and the repo has no PHPUnit suite; check PHP logic with a stubbed `php` script and say wp-env was not run.
- wporg-showcase-2022: `yarn setup:wp` fails in wp-env (it quotes `bash env/setup.sh` as one binary); run `npx wp-env run cli bash env/setup.sh`. Theme patterns are cached, so after adding or moving a `patterns/*.php` file run `wp eval "wp_get_theme()->delete_pattern_cache();"`, and flush the object cache before trusting query-block output.
- wporg-repo-tools: `templates/` are copied into projects by hand and no CI job loads them; check a PHPUnit template by `composer require phpunit/phpunit` in a scratch dir and `DOMDocument::schemaValidate()` against its `vendor/phpunit/phpunit/phpunit.xsd`. Background jobs that read the checkout see whatever branch is checked out when they get there, so read a branch's files with `git show <branch>:<path>`.
